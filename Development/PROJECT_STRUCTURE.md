# Purpose

This document describes how the Project Ascension repository is organised.

Its purpose is to make the project easy to understand, maintain and expand over many years.

The structure should support human creators, future collaborators and AI-assisted development.

As the project evolves, this document should evolve with it.

---

# Repository Philosophy

Project Ascension separates different kinds of knowledge.

Not everything belongs in the same place.

Official design, development documentation and creative exploration each serve different purposes and should remain clearly separated.

This separation allows the project to grow without becoming disorganised.

# Canon

Canon contains the official truth of Project Ascension.

Every document inside Canon represents the current design of the project.

Canon changes deliberately and relatively slowly.

When uncertainty exists, Canon always takes precedence over discussions, research or brainstorming.

Canon currently contains:

- Foundation
- Universe
- Systems
- Marketing
- Glossary

---

# Foundation

Foundation defines why Project Ascension exists.

It contains the project's philosophy, design principles, creative pillars and fundamental models.

Foundation answers questions such as:

- Why are we building this?
- What do we believe?
- Which principles guide every design decision?

---

# Universe

Universe describes the world itself.

It contains the history, timeline, World States, humanity and everything that defines the setting.

Universe answers questions such as:

- What happened?
- How did civilisation change?
- What kind of world do the players enter?

---

# Systems

Systems describe how the Living World functions.

Unlike Universe, Systems are not lore.

They define the simulation itself.

Examples include:

- Life Engine
- Relationship Engine
- Narrative Engine
- Simulation Architecture

Systems explain how the world behaves rather than what it contains.

---

# Marketing

Marketing defines how Project Ascension is communicated to the outside world.

It contains:

- Core Messaging
- Positioning
- Taglines
- Future presentation material

Marketing communicates the identity of the project without defining the simulation itself.

---

# Glossary

Glossary defines the shared language of the project.

Whenever terminology becomes ambiguous, Glossary provides the official definition.

Consistent language creates consistent design.

---

# Development

Development contains documentation describing how Project Ascension itself is built.

It does not describe the game world.

Instead it explains the development process.

Current contents include:

- Academy

Future additions may include:

- Coding Standards
- Development Workflows
- Technical Guidelines

These documents should only be created when genuinely needed.

---

# Project Brain

Project Brain preserves the evolution of the project.

It is intentionally separated from Canon.

Examples include:

- Design Journal
- Decisions
- Brainstorming
- Research
- Inspiration
- Meeting Notes

Information inside Project Brain is valuable but should not be considered canonical until incorporated into Canon.

---

# Assets

Assets contains non-source material used throughout development.

Examples include:

- concept art
- diagrams
- reference images
- audio
- design sketches

---

# Tools

Tools contains utilities that support development.

Examples include:

- generators
- validation scripts
- documentation tools
- conversion utilities

---

# Guiding Principle

Before creating a new document, always ask:

**What kind of knowledge is this?**

Only then decide where it belongs.

A document should always have one clear home.

---

# Living Documentation

Project Ascension is designed as a living project.

Every document should evolve as the project grows.

Documentation should become clearer over time rather than simply becoming larger.

The goal is not to create more documentation.

The goal is to create better knowledge.

---

# Canon Rule

Canon is the single source of truth.

Ideas may begin in discussions.

Concepts may evolve through research.

Design decisions may be explored in Project Brain.

Only when incorporated into Canon do they become official parts of Project Ascension.

---

# Final Statement

A Living World deserves a well-structured project.

Clear organisation allows creativity to grow without creating chaos.

The structure of Project Ascension should evolve with the same care as the world it is designed to support.
