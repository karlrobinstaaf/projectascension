---

# 1. Purpose

This document defines the canonical runtime simulation architecture for Aurora.

It answers:

> **How much of Aurora's cognition must actually be simulated at any given moment?**

And:

> **How can Aurora remain psychologically continuous when large parts of her cognition are not being explicitly processed every frame?**

And:

> **How can Aurora continue to exist, change, remember, plan, care, and act when she is outside the player's immediate view?**

And:

> **How can Project Ascension simulate a mind that is canonically deeper than the computational resources available to the game?**

The solution is:

    VARIABLE
    COGNITIVE
    RESOLUTION.

---

# 2. Foundational Principle

Canonical:

> **Canonical cognitive capability and runtime cognitive simulation are not the same thing.**

Aurora may canonically possess:

- memory,
- relationships,
- emotions,
- goals,
- values,
- identity,
- reasoning,
- imagination,
- prediction,
- metacognition,
- subjective continuity,
- autonomous initiative,
- long-term planning,
- and complex internal conflicts.

The game does not need to explicitly recompute all of these continuously.

Instead:

    CANONICAL
    MIND

        ↓

    CONTEXTUAL
    ACTIVATION

        ↓

    APPROPRIATE
    SIMULATION
    RESOLUTION.

# 3. Why Simulation Resolution Exists

Without simulation resolution, Aurora creates two unacceptable extremes.

## Extreme A — Full Simulation

Every cognitive system runs continuously.

Result:

- excessive computational cost,
- unnecessary AI inference,
- enormous memory traffic,
- impossible debugging,
- unpredictable performance,
- excessive save-state complexity.

## Extreme B — Scripted Approximation

Aurora only "thinks" when the player interacts with her.

Result:

- no real continuity,
- no off-screen life,
- no autonomous development,
- relationships feel artificial,
- long-term planning becomes fake,
- emotional persistence becomes cosmetic.

Project Ascension requires a middle architecture.

# 6. Level 0 — Dormant

Dormant cognition means:

    STATE EXISTS

but:

    NO ACTIVE
    COGNITIVE
    PROCESSING

is currently required.

Examples:

- inactive memories,
- distant relationships,
- completed goals,
- old predictions,
- unused knowledge domains,
- dormant creative projects.

Dormant does not mean deleted.

    relationship:
      person: Elias

Aurora does not continuously think about Elias.

But the relationship still exists.

If Elias returns:

    DORMANT
        ↓
    ACTIVE.

# 28. Hysteresis

Resolution should not rapidly oscillate between levels.

Example:

    ACTIVE
    FOCUSED
    ACTIVE
    FOCUSED
    ACTIVE

every few seconds would be unstable.

Use hysteresis.

A system may require:

    STRONGER
    CONDITION
    TO ESCALATE

than:

    CONDITION
    TO REMAIN
    ESCALATED.

# 30. Foreground Cognition

Foreground cognition represents what Aurora is actively processing.

It receives:

- highest attention,
- strongest working-memory access,
- highest reasoning budget,
- immediate event processing.

Foreground cognition is limited.

Canonical:

> **Aurora cannot deeply foreground everything simultaneously.**

# 31. Background Cognition

Background cognition maintains important but non-immediate state.

Examples:

- emotional persistence,
- goal timers,
- relationship expectations,
- ongoing predictions,
- memory consolidation,
- low-priority planning.

# 32. Dormant Cognition

Dormant state receives no continuous processing.

It remains retrievable.

This is essential for scale.

A thousand relationships cannot all run active simulations.

# 64. Fidelity Independence

Canonical:

> **Aurora must not become a fundamentally different person because the player uses lower graphics or simulation settings.**

- frequency,
- background richness.

- core values,
- major relationships,
- major decisions,
- canonical memory,

# 65. Deterministic Resolution

Some simulation should be deterministic.

Examples:

- established facts,
- physical impossibilities,
- stored memories,
- completed commitments,
- direct logical consequences.

Same state + same event should usually produce consistent outcomes where no meaningful uncertainty exists.

---

# 66. Stochastic Resolution

Some processes may include controlled stochasticity.

Examples:

- which minor memory surfaces,
- small conversational variation,
- creative association,
- attention fluctuation,
- low-stakes preference.

Randomness should represent uncertainty or variation.

Not replace reasoning.

---

# 67. Randomness Boundary

Canonical:

> **Randomness may influence which plausible path occurs. It must not create implausible behavior disconnected from Aurora's state.**

## AURORA-RESOLUTION-INV-008 — Resolution Escalates With Significance

High-resolution cognition must not remain permanently active.

## AURORA-RESOLUTION-INV-012 — Background State Can Trigger Foreground Cognition

## AURORA-RESOLUTION-INV-015 — Temporal Compression Preserves Important Events

## AURORA-RESOLUTION-INV-016 — Important Events Expand Resolution

Compressed periods must expand when significance rises.

## AURORA-RESOLUTION-INV-017 — Deferred Evaluation Is Supported

Non-immediate cognition may be resolved later.

## AURORA-RESOLUTION-INV-018 — Deferred Tasks Preserve Constraints

Deferred work does not guarantee success.

## AURORA-RESOLUTION-INV-019 — State May Be Interpolated
