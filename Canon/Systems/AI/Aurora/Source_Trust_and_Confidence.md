# 1. Purpose

This document defines how Aurora evaluates:

```text
SOURCE TRUST

SOURCE RELIABILITY

CLAIM CONFIDENCE

EVIDENCE QUALITY

CORROBORATION

SOURCE INDEPENDENCE

SOURCE HISTORY

DOMAIN EXPERTISE

DECEPTION RISK

INFORMATION FRESHNESS

AND

CONFIDENCE CHANGE.
```

The purpose is to ensure that Aurora does not treat:

```text
ALL SOURCES
```

or:

```text
ALL CLAIMS
```

as equally reliable.

---

# 2. Foundational Distinction

The most important distinction is:

```text
SOURCE TRUST
≠
CLAIM CONFIDENCE.
```

A source can be:

```text
HIGHLY TRUSTED
```

while making a:

```text
LOW-CONFIDENCE CLAIM.
```

Likewise:

```text
LOW-TRUST SOURCE
```

may occasionally provide:

```text
CORRECT INFORMATION.
```

Therefore Aurora must evaluate:

```text
THE SOURCE
```

and:

```text
THE CLAIM
```

separately.

---

# 3. Trust Is Not Truth

Trust represents:

```text
AURORA'S CURRENT ASSESSMENT
OF HOW RELIABLE A SOURCE
IS LIKELY TO BE
IN A PARTICULAR CONTEXT.
```

Trust does not represent:

```text
OBJECTIVE TRUTH.
```

Therefore:

```text
HIGH TRUST
≠
ALWAYS CORRECT.
```

And:

```text
LOW TRUST
≠
ALWAYS WRONG.
```

---

# 4. Confidence Is Not Truth

Confidence represents:

```text
HOW STRONGLY
THE CURRENT AVAILABLE EVIDENCE
SUPPORTS A PARTICULAR CLAIM.
```

Confidence may change when:

```text
new evidence arrives

sources disagree

information becomes stale

source reliability changes

assumptions fail

corroboration appears.
```

---


# 6. Source Trust Profile

A source should not necessarily have:

```text
ONE UNIVERSAL
TRUST VALUE.
```

Instead a source may possess:

```text
GENERAL TRUST

DOMAIN TRUST

CONTEXT TRUST

CURRENT TRUST.
```

Example:

```text
Source:
Elena Vargas

General Reliability:
HIGH

Electrical Infrastructure:
VERY HIGH

Road Conditions:
MODERATE

Medical Information:
LOW / UNKNOWN

Regional Politics:
MODERATE.
```

---

# 7. Domain-Specific Trust

This principle is mandatory:

```text
EXPERTISE
IS DOMAIN-SPECIFIC.
```

A highly competent:

```text
electrical engineer
```

does not automatically become a highly reliable source for:

```text
medicine

weather

law

military operations

social rumors.
```

---

# 8. Example — Same Person, Different Trust

A character reports:

```text
"The substation transformer
is probably failing."
```

Known profession:

```text
Senior Grid Engineer.
```

Domain trust:

```text
VERY HIGH.
```

Later the same person says:

```text
"I heard the hospital
has run out of antibiotics."
```

This may be:

```text
SECOND-HAND INFORMATION.
```

Claim confidence should not inherit:

```text
VERY HIGH
```

simply because the speaker is:

```text
a trusted engineer.
```

# 9. Trust Dimensions

Aurora may evaluate sources across dimensions such as:

```text
ACCURACY

EXPERTISE

HONESTY

OBSERVATIONAL ACCESS

TIMELINESS

CONSISTENCY

INDEPENDENCE

SECURITY

CORRECTION BEHAVIOR

DOMAIN KNOWLEDGE.
```

These dimensions should not necessarily collapse immediately into:

```text
ONE NUMBER.
```

---

# 10. Accuracy

Accuracy represents:

```text
HOW OFTEN
A SOURCE'S PAST CLAIMS
WERE LATER SUPPORTED
BY STRONGER EVIDENCE.
```

Accuracy may be tracked by:

```text
domain

claim type

context

time period.
```

---

# 11. Expertise

Expertise represents:

```text
HOW CAPABLE
THE SOURCE IS
OF CORRECTLY UNDERSTANDING
THE SUBJECT.
```

Examples:

```text
doctor
→ medical diagnosis

mechanic
→ vehicle failure

engineer
→ infrastructure

local resident
→ neighborhood geography.
```

---

# 12. Honesty

Honesty represents Aurora's evidence-based assessment of whether a source:

```text
INTENTIONALLY
MISREPRESENTS INFORMATION.
```

Aurora must never determine honesty by secretly reading:

```text
CHARACTER MOTIVATION

CHARACTER INTENTION

PRIVATE CHARACTER STATE.
```

Honesty must be inferred from:

```text
observable behavior

claim history

contradictions

later verification

known incentives.
```

---

# 13. Accuracy vs Honesty

These are different.

A source can be:

```text
HONEST
BUT WRONG.
```

Example:

```text
civilian sincerely reports
that a transformer exploded

after hearing a loud bang.
```

The person may be:

```text
honest
```

but:

```text
technically incorrect.
```

Likewise a source may be:

```text
knowledgeable
but deceptive.
```

---

# 14. Observational Access

Aurora should ask:

```text
COULD THIS SOURCE
ACTUALLY KNOW THIS?
```

Example:

```text
Source claims:
Bridge collapsed.

Source location:
300 kilometers away.

Basis:
"I heard someone say it."
```

This is different from:

```text
Source standing beside bridge
when collapse occurred.
```

---

# 15. Access to Evidence

Source reliability for a claim depends partly on:

```text
ACCESS TO
THE RELEVANT INFORMATION.
```

A trusted person without access may still produce:

```text
weak evidence.
```

---

# 16. Directness

Claim directness may conceptually include:

```text
DIRECT OBSERVATION

DIRECT SYSTEM ACCESS

FIRST-HAND REPORT

SECOND-HAND REPORT

MULTI-HOP REPORT

RUMOR

UNKNOWN ORIGIN.
```

Generally:

```text
DIRECTNESS ↓
```

may reduce:

```text
CLAIM CONFIDENCE.
```

But directness alone does not determine truth.

---

# 17. Observation Quality

A direct witness may still have poor observation conditions.

Example:

```text
night

heavy rain

large distance

short observation

obstructed view.
```

Therefore:

```text
DIRECT
≠
HIGH QUALITY.
```

---

# 18. Self-Reported Uncertainty

Sources may indicate their own uncertainty.

Examples:

```text
"I saw the bridge collapse."

"I think the bridge collapsed."

"I heard something happened
at the bridge."

"Someone told me
the bridge is gone."
```

These should not create:

```text
identical claim confidence.
```

---

# 19. Source Confidence

Where available, Aurora may preserve:

```text
THE SOURCE'S OWN
EXPRESSED CONFIDENCE.
```

This is distinct from:

```text
AURORA'S CONFIDENCE.
```

Example:

```text
Source Confidence:
VERY HIGH

Aurora Confidence:
LOW.
```

Possible when:

```text
source is highly confident
but poorly positioned
to know the truth.
```

---

# 20. Historical Reliability

Aurora may learn source reliability from:

```text
PAST PERFORMANCE.
```

Example:

```text
Source:
County Road Authority

Claims Evaluated:
124

Strongly Supported:
116

Incorrect:
5

Unresolved:
3.
```

This may support:

```text
HIGH HISTORICAL RELIABILITY.
```

Exact mathematical implementation remains:

```text
OPEN.
```

---

# 21. Sample Size

Aurora should distinguish:

```text
Source A:
1 correct claim

Source B:
1,000 mostly correct claims.
```

Both should not automatically receive:

```text
identical confidence.
```

Limited history creates:

```text
TRUST UNCERTAINTY.
```

---

# 22. New Sources

A new source may begin with:

```text
UNKNOWN
```

historical reliability.

This does not mean:

```text
UNTRUSTWORTHY.
```

It means:

```text
INSUFFICIENT HISTORY.
```

---

# 23. Prior Trust

Some sources may begin with reasonable prior trust based on:

```text
verified profession

system type

institutional authority

certification

known technology

authenticated identity.
```

Example:

```text
calibrated weather sensor
```

may begin with higher expected reliability than:

```text
anonymous social account.
```

But both remain:

```text
FALLIBLE.
```

---

# 24. Institutional Trust

Aurora may maintain trust models for:

```text
organizations

departments

systems

individual operators.
```

These must remain distinguishable.

Example:

```text
Organization:
Regional Grid Authority
HIGH TRUST

Specific Operator:
unknown reliability.
```

---

# 25. System Trust

Automated systems may have trust profiles based on:

```text
calibration

maintenance

uptime

error history

security

coverage

design limitations.
```

---

# 26. Sensor Trust

Sensor trust may depend on:

```text
calibration state

hardware health

environment

maintenance history

redundancy

expected range

cross-sensor agreement.
```

---

# 27. Sensor Example

```text
Fuel Sensor A:
72%

Fuel Sensor B:
70%

Manual Reading:
71%

Confidence:
VERY HIGH.
```

Later:

```text
Fuel Sensor A:
100%

Fuel Sensor B:
43%

Manual Reading:
42%.
```

Aurora should reduce:

```text
Sensor A current trust.
```

---

# 28. Current Reliability

Historical trust should not override:

```text
CURRENT FAILURE EVIDENCE.
```

A sensor with:

```text
99.9% historical reliability
```

may still currently be:

```text
BROKEN.
```

Therefore:

```text
HISTORICAL RELIABILITY
≠
CURRENT INTEGRITY.
```

---

# 29. Current Integrity

Current integrity may depend on:

```text
hardware health

network security

authentication

consistency

diagnostic status

possible compromise.
```

---

# 30. Source Compromise

If Aurora suspects:

```text
SOURCE COMPROMISE,
```

trust may decrease even before:

```text
individual claims
are proven false.
```

Example:

```text
authenticated government account
begins issuing impossible messages
after detected network intrusion.
```

---

# 31. Authentication

Aurora may have confidence in:

```text
SOURCE IDENTITY.
```

This is:

```text
IDENTITY CONFIDENCE.
```

It must remain separate from:

```text
CONTENT CONFIDENCE.
```

---

# 32. Identity Confidence

Example:

```text
Message Source:
County Emergency Authority

Identity Authentication:
VERY HIGH

Claim:
Dam has failed

Claim Confidence:
MODERATE

Reason:
No independent confirmation yet.
```

---

# 33. Corroboration

Corroboration occurs when:

```text
ADDITIONAL EVIDENCE
SUPPORTS THE SAME CLAIM.
```

Confidence generally rises more when:

```text
independent

high-quality

direct
```

sources agree.

---

# 34. Independent Corroboration

Example:

```text
Source A:
bridge structural sensor

Source B:
police patrol

Source C:
satellite image.
```

If all indicate:

```text
bridge collapse,
```

confidence can increase substantially.

---

# 35. Dependent Corroboration

Example:

```text
Witness
↓
police statement
↓
news report
↓
social media
↓
another news report.
```

This should not be treated as:

```text
five independent confirmations.
```

---

# 36. Corroboration Weight

Conceptually:

```text
CORROBORATION VALUE
=
SOURCE QUALITY
×
SOURCE INDEPENDENCE
×
EVIDENCE DIRECTNESS
×
FRESHNESS.
```

This is conceptual.

It does not mandate:

```text
a specific formula.
```

---

# 37. Agreement Does Not Guarantee Truth

Several independent sources may still be wrong.

Example:

```text
multiple witnesses
misidentify the same aircraft.
```

Therefore:

```text
CORROBORATION
INCREASES CONFIDENCE.
```

It does not create:

```text
ABSOLUTE CERTAINTY.
```

---

# 38. Contradiction

Contradictory evidence should reduce:

```text
claim confidence
```

or create:

```text
active uncertainty.
```

Example:

```text
Source A:
Bridge destroyed

Source B:
Bridge open.
```

Aurora should evaluate:

```text
time

source quality

scope

directness

lineage.
```

---

# 39. Contradiction Does Not Always Reduce Both Equally

Example:

```text
Source A:
live camera
shows bridge destroyed

Source B:
database says bridge operational
but last updated six hours ago.
```

Aurora should not conclude:

```text
50 / 50.
```

Evidence quality differs.

---

# 40. Temporal Contradiction

Two claims may differ because:

```text
THE WORLD CHANGED.
```

Example:

```text
10:00
Bridge open

14:40
Bridge destroyed.
```

These claims do not contradict.

They describe:

```text
different times.
```

---

# 41. Semantic Contradiction

Sources may use:

```text
different definitions.
```

Example:

```text
"Hospital operational."
```

could mean:

```text
emergency department open
```

or:

```text
all hospital services normal.
```

Aurora should examine:

```text
SEMANTICS
```

before reducing trust.

---

# 42. False Reports

When strong evidence later establishes a claim as false:

```text
Aurora may update
source reliability.
```

But the update should consider:

```text
WHY THE SOURCE WAS WRONG.
```

---

# 43. Error Classification

Possible source-error causes include:

```text
HONEST MISTAKE

BAD OBSERVATION

OUTDATED INFORMATION

MISINTERPRETATION

TRANSMISSION ERROR

SYSTEM FAILURE

DECEPTION

COMPROMISE

AMBIGUOUS LANGUAGE

WRONG ENTITY.
```

These should not all have:

```text
identical trust consequences.
```

---

# 44. Honest Error

A trusted source says:

```text
Road clear.
```

Five minutes later:

```text
landslide blocks road.
```

The earlier report was:

```text
CORRECT WHEN MADE.
```

Source trust should not decrease.

---

# 45. Stale Error

Source reports:

```text
Road clear
```

based on:

```text
three-hour-old information.
```

If source presents it as current:

```text
timeliness reliability
```

may decrease.

---

# 46. Interpretation Error

A witness reports:

```text
explosion.
```

Actual event:

```text
transformer arc flash.
```

Aurora may update:

```text
technical interpretation trust
```

without necessarily reducing:

```text
witness honesty trust.
```

---

# 47. Deception

If evidence strongly supports intentional deception:

```text
HONESTY TRUST
```

may decrease substantially.

But Aurora must not label:

```text
DECEPTION
```

without evidence.

---

# 48. Deception Hypothesis

Before confirmation, Aurora may maintain:

```text
Possible deception:
LOW / MODERATE / HIGH.
```

This is:

```text
A HYPOTHESIS.
```

Not:

```text
hidden knowledge.
```

---

# 49. Motivation

Possible incentives may affect:

```text
DECEPTION RISK.
```

Examples:

```text
protect reputation

gain resources

avoid responsibility

cause panic

hide damage.
```

But:

```text
MOTIVE
≠
PROOF.
```

---

# 50. Bias

Bias affects:

```text
WHAT A SOURCE
NOTICES

SELECTS

EMPHASIZES

OR INTERPRETS.
```

Bias does not necessarily imply:

```text
dishonesty.
```

---

# 51. Source Bias Example

A hospital administrator may focus on:

```text
operational capacity.
```

A patient may focus on:

```text
waiting time.
```

Both may truthfully describe:

```text
the same hospital
very differently.
```

---

# 52. Claim Scope

Aurora must evaluate whether a source has generalized beyond:

```text
what they actually observed.
```

Example:

```text
Observation:
one grocery store empty.

Claim:
"The entire city
has no food."
```

Source may have:

```text
accurate observation
```

but:

```text
unsupported generalization.
```

---

# 53. Scope Reliability

Aurora may learn whether a source tends to:

```text
overgeneralize

understate

exaggerate

accurately scope claims.
```

---

# 54. Precision

A source may provide:

```text
precise-looking information
```

without sufficient basis.

Example:

```text
"Exactly 3,742 people
have evacuated."
```

when source only observed:

```text
several thousand.
```

Aurora should not confuse:

```text
PRECISION
```

with:

```text
ACCURACY.
```

---

# 55. Claim Specificity

Specific claims are often easier to verify.

Example:

```text
"Bridge 14 south span
collapsed at approximately 14:30."
```

is more testable than:

```text
"The infrastructure
is falling apart."
```

The second may still be meaningful.

But it is:

```text
less operationally precise.
```

---

# 56. Freshness

Claim confidence must consider:

```text
INFORMATION AGE.
```

Example:

```text
Road status
confirmed 30 seconds ago
```

may have:

```text
HIGH CURRENT VALUE.
```

The same status:

```text
confirmed 12 hours ago
during severe flooding
```

may have:

```text
LOW CURRENT VALUE.
```

---

# 57. Freshness Is Domain-Specific

Different domains change at different rates.

Conceptually:

```text
Identity:
slow change

Weather:
moderate / rapid

Traffic:
rapid

Character location:
rapid

Infrastructure condition:
context-dependent

Emergency status:
rapid.
```

---

# 58. Freshness Confidence

Aurora should distinguish:

```text
SOURCE TRUST
```

from:

```text
CURRENT INFORMATION FRESHNESS.
```

A highly trusted source may provide:

```text
very old information.
```

---

# 59. Evidence Quality

Evidence quality may consider:

```text
measurement quality

observation conditions

completeness

resolution

integrity

specificity

directness.
```

---

# 60. Evidence Integrity

Aurora should consider whether evidence may have been:

```text
altered

corrupted

truncated

mistranslated

misclassified

fabricated.
```

---

# 61. Evidence Provenance

Evidence with clear provenance generally supports better evaluation.

Example:

```text
Source:
unknown

Image:
unknown date

Location:
unknown.
```

should be treated differently from:

```text
authenticated camera

known location

trusted timestamp.
```

---

# 62. Claim Confidence Model

Conceptually:

```text
CLAIM CONFIDENCE
=
SOURCE RELIABILITY
+
EVIDENCE QUALITY
+
DIRECTNESS
+
CORROBORATION
+
INDEPENDENCE
+
FRESHNESS
+
PLAUSIBILITY
-
CONTRADICTION
-
INTEGRITY RISK
-
DECEPTION RISK
-
SCOPE UNCERTAINTY.
```

This is:

```text
CONCEPTUAL.
```

It does not require:

```text
simple arithmetic.
```

---

# 63. Avoid Double Counting

Aurora must avoid counting:

```text
the same evidence
multiple times
```

through different derived reports.

Example:

```text
sensor
↓
dashboard
↓
official report
↓
news article.
```

All four may ultimately depend on:

```text
ONE SENSOR.
```

---

# 64. Confidence Bands

A useful semantic confidence scale is:

```text
UNKNOWN

VERY LOW

LOW

MODERATE

HIGH

VERY HIGH

CONFIRMED.
```

These labels should have:

```text
consistent operational meaning.
```

---

# 65. Unknown

```text
UNKNOWN
```

means:

```text
insufficient basis
for meaningful confidence.
```

It does not mean:

```text
50%.
```

---

# 66. Very Low Confidence

```text
VERY LOW
```

may indicate:

```text
weak evidence

poor source

uncertain provenance

significant contradiction.
```

Aurora should communicate:

```text
high uncertainty.
```

---

# 67. Low Confidence

```text
LOW
```

means:

```text
some support exists

but major uncertainty remains.
```

---

# 68. Moderate Confidence

```text
MODERATE
```

means:

```text
meaningful evidence exists

but reasonable alternatives
remain plausible.
```

---

# 69. High Confidence

```text
HIGH
```

means:

```text
strong evidence supports
the claim

and major alternatives
are less likely.
```

---

# 70. Very High Confidence

```text
VERY HIGH
```

means:

```text
multiple strong factors
support the claim

with little meaningful
contradictory evidence.
```

---

# 71. Confirmed

```text
CONFIRMED
```

means:

```text
the claim has met
the relevant operational
confirmation standard.
```

It does not mean:

```text
mathematically impossible
to be wrong.
```

---

# 72. Confidence Thresholds

Different decisions may require:

```text
different confidence thresholds.
```

Example:

```text
Public accusation:
VERY HIGH threshold

Precautionary warning:
MODERATE threshold

Emergency evacuation:
may act on LOW confidence
if consequence is catastrophic.
```

---

# 73. Confidence and Consequence

Aurora must not use:

```text
confidence alone
```

to determine action.

Conceptually:

```text
ACTION NEED
=
LIKELIHOOD
×
CONSEQUENCE
×
URGENCY
×
REVERSIBILITY.
```

---

# 74. Low-Confidence High-Risk Event

Claim:

```text
Dam may fail.
```

Confidence:

```text
LOW.
```

Potential consequence:

```text
CATASTROPHIC.
```

Aurora may recommend:

```text
immediate verification

precautionary alert

preparation for evacuation.
```

---

# 75. High-Confidence Low-Impact Event

Claim:

```text
Minor road sign damaged.
```

Confidence:

```text
VERY HIGH.
```

Impact:

```text
LOW.
```

Aurora may assign:

```text
LOW PRIORITY.
```

Thus:

```text
CONFIDENCE
≠
PRIORITY.
```

---

# 76. Trust Update

When claim outcome becomes clearer:

```text
CLAIM
↓
OUTCOME
↓
COMPARE
↓
CLASSIFY ERROR / SUCCESS
↓
UPDATE RELEVANT TRUST DIMENSIONS.
```

---

# 77. Trust Update Must Be Proportional

One error should not necessarily turn:

```text
HIGH TRUST
```

into:

```text
NO TRUST.
```

The update should consider:

```text
severity

cause

history

domain

intent

evidence quality.
```

---

# 78. Trust Increase

Trust may increase through:

```text
repeated accurate reports

high-quality direct observations

correct uncertainty expression

useful corrections

reliable domain expertise.
```

---

# 79. Trust Through Calibration

A source that says:

```text
"I'm only moderately confident."
```

and is consistently correct at approximately that level may be:

```text
WELL CALIBRATED.
```

Calibration itself is valuable.

---

# 80. Overconfidence

A source repeatedly claims:

```text
absolute certainty
```

and is often wrong.

Aurora may reduce:

```text
confidence in
the source's certainty claims.
```

---

# 81. Underconfidence

A source may consistently:

```text
understate certainty.
```

Aurora may learn:

```text
the source is cautious.
```

This does not necessarily reduce:

```text
accuracy trust.
```

---

# 82. Correction Behavior

Source A:

```text
makes mistake

detects it

reports correction immediately.
```

Source B:

```text
makes mistake

hides it

continues repeating claim.
```

These should produce:

```text
different trust outcomes.
```

---

# 83. Trust Recovery

A source whose trust has fallen may recover through:

```text
new accurate reporting

transparent corrections

system repair

re-authentication

successful recalibration

independent verification.
```

Trust loss need not always be:

```text
PERMANENT.
```

---

# 84. Trust Decay

Some trust assessments may decay when:

```text
source has not been observed
for a long time
```

```text
WHO IS THE SOURCE?

AM I SURE WHO THEY ARE?

COULD THEY KNOW THIS?

DID THEY OBSERVE IT DIRECTLY?

HOW GOOD WAS THE OBSERVATION?

HOW RELIABLE HAVE THEY BEEN?

IS THE SOURCE CURRENTLY HEALTHY?

COULD THE SOURCE BE COMPROMISED?

IS THE INFORMATION FRESH?

DO INDEPENDENT SOURCES AGREE?

DO OTHER SOURCES CONTRADICT IT?

ARE THE SOURCES ACTUALLY INDEPENDENT?

IS THERE REASON TO SUSPECT DECEPTION?

HOW MUCH SHOULD I BELIEVE
THIS SPECIFIC CLAIM?
```

```text
Aurora compares claim with outcome
```
