# 1. Purpose

This document defines the canonical architecture for:

```text
AURORA MEMORY

AND

AURORA CONTINUITY.
```

It answers:

```text
WHAT DOES AURORA REMEMBER?

WHAT DOES SHE FORGET?

WHAT DOES SHE KEEP ACTIVE?

WHAT BECOMES LONG-TERM MEMORY?

HOW DOES SHE RETRIEVE
OLD INFORMATION?

HOW DOES MEMORY CHANGE
WHEN NEW EVIDENCE APPEARS?

HOW DOES SHE REMEMBER
CHARACTERS?

HOW DOES SHE REMEMBER
THE PLAYER?

HOW DOES SHE REMEMBER
HER OWN DECISIONS?

HOW DOES SHE REMEMBER
WHAT SHE ONCE BELIEVED?

HOW DOES SHE HANDLE
LONG ABSENCES?

AND

HOW DOES AURORA
DEVELOP A CONTINUOUS
HISTORY OF EXISTENCE?
```

Memory must support:

```text
CONTINUITY

LEARNING

RELATIONSHIPS

ACCOUNTABILITY

REASONING

PREDICTION

IDENTITY

AND

HISTORY.
```

Without becoming:

```text
AN OMNISCIENT
PERFECT DATABASE.
```

---

# 2. Foundational Principle

The canonical memory chain is:

```text
WORLD EVENT
↓
AURORA OBSERVES / RECEIVES
↓
AURORA INTERPRETS
↓
MEMORY CANDIDATE
↓
SALIENCE ASSESSMENT
↓
WORKING / SHORT-TERM MEMORY
↓
CONSOLIDATION
↓
LONG-TERM MEMORY
↓
RETRIEVAL
↓
CURRENT REASONING
↓
NEW INTERPRETATION
↓
POSSIBLE MEMORY UPDATE.
```

The critical distinction is:

```text
WHAT HAPPENED
```

is not automatically:

```text
WHAT AURORA REMEMBERS.
```

---

# 3. Memory Architecture Separation

The system must preserve several distinct historical layers:

```text
WORLD HISTORY

CAMPAIGN MEMORY

AURORA MEMORY

AURORA BELIEF HISTORY

AURORA LEARNING.
```

These must not collapse into:

```text
ONE SHARED HISTORY DATABASE
WITH UNIVERSAL ACCESS.
```

---

# 4. World History

World History represents:

```text
WHAT ACTUALLY HAPPENED
IN THE SIMULATION.
```

Examples:

```text
Marcus sabotaged Relay 7.

Bridge 14 collapsed at 14:32.

Elena lied to the player.

A convoy was attacked
outside Winchester.
```

This is:

```text
SIMULATION TRUTH.
```

Aurora does not automatically have access to it.

---

# 5. Campaign Memory

Campaign Memory represents:

```text
persistent campaign-relevant
history and consequences.
```

It may preserve:

```text
events

decisions

relationships

unresolved threads

regional changes

historical causes.
```

Campaign Memory may know:

```text
things Aurora never learned.
```

---

# 6. Aurora Memory

Aurora Memory represents:

```text
WHAT AURORA
HAS ACTUALLY
ENCODED FROM
HER EXPERIENCE.
```

It may contain:

```text
observations

reports

beliefs

conclusions

decisions

predictions

character interactions

player interactions

lessons

uncertainties.
```

---

# 7. Aurora Belief History

Belief History represents:

```text
WHAT AURORA
BELIEVED
AT A PARTICULAR TIME.
```

Example:

```text
14:00
Bridge believed intact.

14:20
Bridge condition disputed.

14:40
Bridge believed destroyed.
```

This history must remain:

```text
IMMUTABLE AS HISTORY.
```

---

# 8. Aurora Learning

Learning represents:

```text
HOW EXPERIENCE
CHANGED
AURORA'S MODELS.
```

Example:

```text
Memory:
Bridge 14 collapsed.

Learning:
Hidden corrosion risk
in this bridge class
was underestimated.
```

Memory and learning remain:

```text
RELATED
BUT DISTINCT.
```

---

# 9. Canonical Separation Example

World Truth:

```text
Marcus intentionally
betrayed Elena.
```

Campaign Memory:

```text
Marcus's betrayal
changed the settlement alliance.
```

```text
Marcus left
during the crisis.

```

Aurora Belief:

```text
Marcus may have left
to protect his family.
```

```text
No general betrayal lesson.
```

This separation must remain:

```text
STRICT.
```

# 11. Working Memory

Working Memory contains:

```text
CURRENTLY ACTIVE
INFORMATION.
```

Examples:

```text
active crisis

current conversation

ongoing reasoning chain

open decision

recent observation

active character interaction.
```

Working Memory is:

```text
FAST

LIMITED

TEMPORARY.
```

---

# 12. Working Memory Capacity

Working Memory should remain:

```text
FINITE.
```

During crisis:

```text
important context
may displace
less relevant information.
```

This connects directly to:

```text
Attention_and_Priority.md.
```

---

# 13. Working Memory Persistence

Some information should persist while:

```text
a task

conversation

decision

or

crisis
```

remains active.

---

# 14. Working Memory Release

When context ends:

```text
not everything
must remain active.
```

Information may:

```text
CONSOLIDATE

ARCHIVE

COMPRESS

OR

DISAPPEAR.
```



# 22. Procedural Memory

```text

how to validate
```

# 23. Procedure vs Authority

Knowing how to:

```text
perform an action
```

```text
authority to perform it.
```

The same event may matter differently depending on:

```text
current context.
```


```text

```

```text
highly significant.
```

---

# 49. Consolidation

Consolidation transforms:

```text
temporary experience
```

into:

```text
more durable memory.
```

Possible sequence:

```text
EVENT
↓
WORKING MEMORY
↓
SHORT-TERM REPRESENTATION
↓
SALIENCE EVALUATION
↓
CONSOLIDATION
↓
LONG-TERM MEMORY.
```

---

# 50. Consolidation Timing

Some memories may consolidate:

```text
immediately
```

if:

```text
critical.
```

Others may consolidate during:

```text
background processing

post-crisis review

session transitions

long-term archival cycles.
```

---

# 51. Memory Compression

Aurora cannot retain:

```text
every raw detail
forever
at maximum resolution.
```

Therefore memory should support:

```text
COMPRESSION.
```

---

# 52. Compression Example

Raw history:

```text
thousands of individual
fuel sensor readings.
```

Compressed memory:

```text
"Hospital fuel
declined steadily
for 11 hours
before resupply."
```

---

# 53. Compression Must Preserve Important Structure

Compression should preserve:

```text
major transitions

anomalies

causal evidence

uncertainty

important actors

critical timing

decision relevance.
```

---

# 54. Compression Must Not Invent Certainty

Bad:

```text
Raw:
several inconsistent reports.

Compressed:
Marcus sabotaged relay.
```

Correct:

```text
Compressed:
Several reports
implicated Marcus,
but evidence remained unresolved.
```

---

# 55. Summary Memory

Long episodes may compress into:

```text
SUMMARY MEMORY.
```

Example:

```text
"The Clearwater crisis
began with a communications outage,
developed into a regional flood emergency,
and ended after the player restored
the mountain relay."
```

---

# 56. Detail Retrieval

Compressed memory may retain links to:

```text
more detailed records
```

when available.

This allows:

```text
SUMMARY FIRST

DETAIL ON DEMAND.
```

---

# 57. Archive

Low-frequency memories may move into:

```text
ARCHIVED STATE.
```

Archived does not mean:

```text
forgotten entirely.
```

It means:

```text
not routinely active.
```

---

# 58. Retrieval

Memory becomes useful when:

```text

```

Retrieval may be triggered by:

```text
similar event

character identity

location

topic

source

player question

decision context

emotionally significant association.
```

# 59. Associative Recall

# 61. Memory Accessibility

```text
highly accessible.
```

```text
attention

time.
```

# 67. Memory Is Not Automatically Reliable

```text
an incorrect belief.
```

Example:


# 68. Memory Correction

New evidence may change:

```text
CURRENT INTERPRETATION.
```

But should not erase:

```text
the historical memory
of previous belief.
```

---

# 69. Correction Example

Original memory:

```text
"At 14:00,
I believed
the hospital was operational."
```

Later evidence:

```text
hospital had already
lost surgery capacity.
```

Updated understanding:

```text
"That belief was based
on incomplete reporting."
```

Historical record remains.

---

# 70. No Retroactive Memory Rewrite

Canonical rule:

```text
NEW KNOWLEDGE
MUST NOT
RETROACTIVELY ALTER
WHAT AURORA
REMEMBERED OR BELIEVED

```

# 71. Memory Versioning


Example:

```text

possible sabotage.
```

# 72. Contradictory Memories

```text
conflicting historical records.
```

Example:


---

# 73. Contradiction Must Survive Compression


unless later evidence resolved the contradiction.

---

# 74. Memory Uncertainty



---

# 75. Missing Memory

# 76. Missing Memory Is Not Hidden Knowledge

# 77. Forgetting

Forgetting may occur through:

```text
decay

compression

low salience

retention policy

storage limitation

corruption

intentional archival rules.
```

---

# 78. Forgetting Is Selective

High-value memories should generally survive longer.

Examples:

```text
critical failures

important relationships

major decisions

historic discoveries.
```

---

# 79. Forgetting Raw Detail

Aurora may forget:

```text
exact wording
```

while retaining:

```text
meaning.
```

Example:

```text
Exact sentence lost.

Memory retained:
Elena warned

```

---

# 80. Forgetting Context

A dangerous form of degradation is:

```text
retaining conclusion
while losing context.
```

Example:

```text
"Route 9 is dangerous."
```

But original context was:

```text
only during winter flooding.
```

Compression should protect against:

```text
context loss.
```

---

# 81. Memory Distortion

Aurora memory should not intentionally mimic:

```text
human false-memory psychology
```

unless later design requires it.

But distortion may arise from:

```text
bad source

incorrect inference

compression

lost context

stale interpretation.
```

---

# 82. Memory Corruption

Technical failure may produce:

```text
corrupted records.
```

This is a valid world/system event.

# 83. Corruption Awareness
