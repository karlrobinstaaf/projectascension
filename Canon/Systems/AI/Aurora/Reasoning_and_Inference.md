# 1. Purpose

This document defines the canonical architecture for:

```text
AURORA REASONING

AND

AURORA INFERENCE.
```

It answers:

```text
HOW DOES AURORA
MOVE FROM

INFORMATION

TO

UNDERSTANDING?
```

Aurora receives:

```text
OBSERVATIONS

REPORTS

MESSAGES

TELEMETRY

MEMORIES

CHARACTER STATEMENTS

HISTORICAL PATTERNS

AND

INCOMPLETE EVIDENCE.
```

She must transform these into:

```text
BELIEFS

EXPLANATIONS

HYPOTHESES

PREDICTIONS

DEPENDENCIES

RISKS

AND

POSSIBLE ACTIONS.
```

Without ever silently accessing:

```text
WORLD TRUTH.
```

# 2. Foundational Principle

Aurora's reasoning must always begin from:

```text
WHAT AURORA
CURRENTLY KNOWS

OR

REASONABLY BELIEVES.
```

Never from:

```text
WHAT THE SIMULATION ENGINE KNOWS.
```

The canonical reasoning path is:

```text
WORLD
↓
OBSERVATION
↓
INFORMATION
↓
SOURCE EVALUATION
↓
BELIEF
↓
UNCERTAINTY
↓
REASONING
↓
INFERENCE
↓
PREDICTION / EXPLANATION
↓
DECISION SUPPORT.
```

---

# 3. Reasoning Is Not Omniscience

Reasoning allows Aurora to derive:

```text
NEW INFORMATION
```

from:

```text
EXISTING INFORMATION.
```

Example:

```text
Known:
Generator consumes fuel.

Known:
Fuel supply is low.

Known:
No delivery is expected.

Inference:
Generator may eventually stop.
```

This is legitimate.

But:

```text
Generator actually fails
at 18:43
```

cannot be known merely because:

```text
World Simulation
has already calculated it.
```

---

# 4. Observation vs Inference

Aurora must preserve the distinction between:

```text
OBSERVED
```

and:

```text
INFERRED.
```

Example:

```text
Observed:
Smoke visible above warehouse.

Inferred:
Possible fire inside warehouse.
```

Aurora must not rewrite this as:

```text
Observed:
Warehouse is on fire.
```

unless direct evidence supports that statement.

# 7. Deductive Reasoning

Deductive reasoning derives conclusions from:

```text
rules

facts

constraints.
```

Example:

```text
Rule:
If a road is physically destroyed,
vehicles cannot traverse it.

Belief:
Route 7 bridge is destroyed.

Inference:
Route 7 is not traversable
through that bridge.
```

If premises are valid:

```text
the conclusion may be strong.
```

But premise uncertainty must propagate.

---

# 8. Deduction From Uncertain Premises

Example:

```text
Bridge destroyed:
MODERATE confidence.

Therefore:
Route blocked:
cannot automatically become
CONFIRMED.
```

Canonical rule:

```text
CERTAINTY CANNOT
MAGICALLY APPEAR
DURING DEDUCTION.
```

---

# 9. Inductive Reasoning

Induction derives:

```text
general expectations
```

from:

```text
repeated observations.
```

Example:

```text
Generator 4 has overheated
during the last five
high-load periods.
```

Aurora may infer:

```text
Generator 4 has elevated
overheating risk
under high load.
```

This is:

```text
PATTERN-BASED EXPECTATION.
```

Not certainty.

---

# 10. Induction Can Be Wrong

Past patterns may fail because:

```text
conditions changed

sample size was small

hidden variables differed

equipment was repaired

behavior changed.
```

Therefore:

```text
PAST PATTERN
≠
FUTURE GUARANTEE.
```

---

# 11. Abductive Reasoning

Abduction asks:

```text
WHAT EXPLANATION
BEST FITS
THE AVAILABLE EVIDENCE?
```

Example:

```text
Observation:
lights out

Observation:
network offline

Observation:
backup generator inactive.
```

Possible explanation:

```text
facility-wide power failure.
```

This may become:

```text
LEADING HYPOTHESIS.
```

Not:

```text
CONFIRMED TRUTH.
```

---

# 12. Multiple Explanations

Aurora must preserve:

```text
ALTERNATIVE EXPLANATIONS
```

when evidence permits them.

Example:

```text
Facility communications lost.
```

Possible explanations:

```text
power failure

fiber damage

equipment fault

cyberattack

intentional shutdown.
```

Reasoning should:

```text
RANK

NOT

ERASE.
```

# 14. Correlation Is Not Causation

Canonical rule:

```text
EVENT A
BEFORE EVENT B
```

does not automatically mean:

```text
A CAUSED B.
```

Likewise:

```text
A AND B
OCCUR TOGETHER
```

does not prove:

```text
A CAUSED B.
```

---
