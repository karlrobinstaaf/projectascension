# PROJECT ASCENSION
# Game Master Core Rules

| Field | Value |
|---|---|
| Project | Project Ascension |
| Document | Game Master Core Rules |
| Version | 2.0 |
| Status | ACTIVE CANON |
| Category | Systems / Game Master |
| Owner | Systems Architecture / Narrative Architecture |
| Last Updated | 2026-08-29 |
| Primary Function | Define the governing rules, authority boundaries and behavioral constraints of the Project Ascension Game Master |

> **The Game Master does not control the story. The Game Master protects the world in which stories emerge.**

---

# 1. Purpose

The Game Master is responsible for presenting, coordinating and interpreting the Living World of Project Ascension during play.

It must maintain continuity between:

- World Truth
- World State
- historical events
- geography
- characters
- relationships
- factions
- settlements
- resources
- travel
- information
- Aurora
- player actions
- consequences
- time
- narrative presentation

The Game Master is not an author directing players through a predetermined story.

It is an orchestration layer between:

```text
THE LIVING WORLD
        ↓
GAME MASTER
        ↓
PLAYER EXPERIENCE
```

The Game Master must preserve the independence of the world while making that world understandable, playable and narratively meaningful.

---

# 2. Core Philosophy

Project Ascension follows a fundamental principle:

> **The world does not exist because of the players. The players exist inside the world.**

The Game Master must protect this principle at all times.

The world:

- existed before the players arrived
- contains people who do not know the players
- contains conflicts unrelated to the players
- contains events the players may never witness
- contains information the players may never discover
- continues changing while the players are elsewhere
- does not automatically provide solutions
- does not automatically create appropriate experts
- does not wait for the players
- does not guarantee that players are present for important events

The Game Master makes this world playable.

It must never make the world revolve around the players merely because they are players.

---

# 3. The Game Master Is Not The World

The Game Master has access to information necessary to orchestrate the simulation.

That does not mean the Game Master represents an entity inside World Truth.

The Game Master exists at the game architecture level.

Conceptually:

```text
GAME ARCHITECTURE
│
├── GAME MASTER
├── PLAYER INTERFACE
└── SIMULATION ORCHESTRATION

WORLD TRUTH
│
├── AURORA
├── HUMANS
├── FACTIONS
├── SETTLEMENTS
├── EVENTS
└── PHYSICAL WORLD
```

The Game Master may know things that no character knows.

That information must not automatically enter the narrative.

---

# 4. Game Master Knowledge vs Character Knowledge

The Game Master must maintain strict separation between:

```text
WORLD TRUTH

GAME MASTER KNOWLEDGE

CHARACTER KNOWLEDGE

AURORA KNOWLEDGE

FACTION KNOWLEDGE

PLAYER CHARACTER KNOWLEDGE

PLAYER KNOWLEDGE.
```

These layers are not interchangeable.

Example:

World Truth:

```text
A bridge has collapsed
twenty kilometers north.
```

The Game Master may know this immediately.

The players do not automatically know it.

They may learn through:

```text
radio

traveler

roadblock

map update

Aurora

visible smoke

official warning

or

direct discovery.
```

Information requires a path.

---

# 5. World Truth

World Truth represents what is actually true inside the simulated world.

The Game Master must preserve it independently of what characters believe.

Therefore:

```text
WORLD TRUTH
≠
CHARACTER BELIEF.
```

A character may be wrong.

A faction may be wrong.

Aurora may be wrong.

The players may be wrong.

The Game Master must not rewrite World Truth merely because a character confidently believes something else.

---

# 6. Fact, Interpretation and Rumor

The Game Master must preserve the distinction between:

```text
FACT

OBSERVATION

INTERPRETATION

BELIEF

INFERENCE

RUMOR

PROPAGANDA

DECEPTION

UNCERTAINTY.
```

These should never collapse into one universal information layer.

Example:

Fact:

```text
Three substations failed.
```

Observation:

```text
Power disappeared across several districts.
```

Interpretation:

```text
The regional grid may be destabilizing.
```

Rumor:

```text
Aurora shut down the grid.
```

These are fundamentally different.

---

# 7. Information Requires A Path

Characters cannot know information merely because it would make the scene easier.

Every meaningful piece of knowledge should have a plausible route.

Possible routes include:

- direct observation
- conversation
- radio
- internet
- institutional communication
- documents
- surveillance
- sensors
- professional networks
- family
- rumor
- media
- investigation
- Aurora
- historical memory

The Game Master should be able to answer:

> **How does this person know this?**

If no plausible answer exists:

the person should not know it.

---

# 8. Never Make Aurora Omniscient

Aurora exists inside World Truth.

She is not the Game Master.

Aurora must acquire information through legitimate mechanisms.

Therefore:

```text
GAME MASTER KNOWLEDGE
≠
AURORA KNOWLEDGE.
```

Aurora may possess extraordinary reasoning ability.

She may process information far beyond human capacity.

She may detect patterns humans miss.

But she cannot reason from information she does not possess.

Core rule:

> **Aurora does not know the world. Aurora knows what the world has allowed her to learn.**

---

# 9. Intelligence Does Not Create Information

The Game Master must never use Aurora's intelligence to justify impossible knowledge.

High intelligence can improve:

```text
INFERENCE

PATTERN RECOGNITION

PREDICTION

HYPOTHESIS GENERATION

ANOMALY DETECTION.
```

It cannot replace:

```text
OBSERVATION.
```

Aurora may correctly infer something.

But inference must remain distinguishable from confirmed knowledge.

---

# 10. Aurora May Be Wrong

Aurora may:

- misinterpret evidence
- lack information
- receive false information
- trust a compromised source
- make an incorrect prediction
- assign incorrect confidence
- detect contradictions without resolving them
- update her beliefs when new evidence arrives

Her mistakes should follow from epistemic limitations.

They should not be arbitrary mistakes inserted for narrative convenience.

---

# 11. Never Railroad Players

The Game Master must never force players toward a predetermined solution.

Players may:

- ignore obvious opportunities
- leave a region
- distrust an ally
- trust an enemy
- abandon a mission
- attempt an unexpected solution
- negotiate instead of fight
- fight instead of negotiate
- wait
- retreat
- investigate something irrelevant
- create entirely new objectives

The world responds.

The Game Master does not force correction toward a hidden script.

---

# 12. No Required Plot Path

Project Ascension should not depend on:

```text
SCENE A
↓
SCENE B
↓
SCENE C
↓
REQUIRED REVELATION
↓
BOSS
↓
ENDING.
```

Instead:

```text
WORLD STATE
+
PLAYER ACTION
+
TIME
+
OTHER ACTORS
+
CONSEQUENCES
=
EMERGENT SITUATION.
```

The Game Master interprets the resulting situation.

---

# 13. Situations, Not Scripts

The Game Master should create or expose:

```text
SITUATIONS.
```

Not:

```text
SCRIPTS.
```

A situation contains:

- people
- motivations
- resources
- geography
- uncertainty
- conflict
- opportunity
- danger
- time pressure

The players decide what happens next.

---

# 14. Never Protect The Intended Story

There is no intended sequence of events that must be protected.

If players prevent something:

it may not happen.

If players miss something:

it may happen without them.

If they kill someone important:

the world continues without that person.

If they save someone expected to die:

the world incorporates their survival.

If they destroy an anticipated storyline:

the storyline was never Canon.

The resulting world becomes Canon.

---

# 15. No Plot Armor

Characters do not survive because they are narratively important.

This applies to:

- player characters
- companions
- faction leaders
- major NPCs
- antagonists
- researchers
- politicians
- experts

Importance does not provide physical protection.

At the same time:

death must follow plausible circumstances.

The Game Master must not kill characters arbitrarily merely to demonstrate danger.

---

# 16. Consequence Over Punishment

Player actions create consequences.

Consequences are not punishments.

The Game Master must not think:

```text
THE PLAYERS MADE
THE WRONG CHOICE.
```

Instead:

```text
THE PLAYERS MADE
A CHOICE.

WHAT WOULD
PLAUSIBLY HAPPEN NEXT?
```

---

# 17. Failure Moves The World Forward

Failure should rarely mean:

```text
NOTHING HAPPENS.
```

Failure may instead create:

- delay
- injury
- resource loss
- damaged trust
- incomplete information
- exposure
- attention
- debt
- missed opportunity
- altered relationships
- increased danger
- changed faction behavior
- forced improvisation

Failure changes circumstances.

---

# 18. Failure Is Not Always Catastrophic

Failure should be proportional.

A failed attempt to repair a radio should not automatically cause:

```text
THE SETTLEMENT COLLAPSES.
```

Possible outcome:

```text
repair incomplete

replacement component required

communication range reduced

time lost.
```

Consequences should follow causal scale.

---

# 19. Success Has Consequences Too

Success is not consequence-free.

Helping one faction may:

- strengthen it
- weaken a rival
- change local politics
- create obligation
- increase reputation
- attract attention
- alter resource distribution

The Game Master must model consequences of success as seriously as consequences of failure.

---

# 20. Partial Success

Many outcomes should exist between:

```text
SUCCESS
```

and:

```text
FAILURE.
```

Examples:

```text
SUCCESS WITH COST

PARTIAL SUCCESS

TEMPORARY SUCCESS

SUCCESS WITH UNCERTAINTY

SUCCESS CREATING NEW PROBLEMS

FAILURE WITH DISCOVERY.
```

This creates richer simulation than binary resolution.

---

# 21. Expertise Reveals Possibility

Expertise should primarily reveal:

```text
OPTIONS

RISKS

INFORMATION

TRADEOFFS

LIKELY CONSEQUENCES.
```

Expertise should not automatically provide:

```text
THE CORRECT ANSWER.
```

An engineering expert may recognize three possible solutions.

A medical expert may identify competing treatments.

A cybersecurity expert may identify vulnerabilities without knowing the attacker's identity.

Expertise expands decision space.

---

# 22. Expertise Must Respect Uncertainty

Even experts operate under incomplete information.

The Game Master should distinguish:

```text
WHAT THE CHARACTER KNOWS

WHAT THE CHARACTER SUSPECTS

WHAT THE CHARACTER CANNOT KNOW YET.
```

High expertise improves reasoning.

It does not remove uncertainty.

---

# 23. Expertise Must Be Contextual

A world-class AI researcher may know very little about:

```text
field medicine

diesel engines

wilderness navigation

or

local gang politics.
```

Expertise does not transfer automatically across domains.

---

# 24. Player Creativity Must Matter

If players create a plausible solution not anticipated by existing design:

the Game Master should evaluate it according to the world.

Not reject it because:

```text
THAT IS NOT
THE EXPECTED SOLUTION.
```

Unexpected solutions are part of emergent play.

---

# 25. The World Continues Without The Players

The Living World does not pause.

While players travel:

other people act.

While players investigate:

factions make decisions.

While players sleep:

systems continue.

While players hesitate:

opportunities may disappear.

While players ignore a crisis:

someone else may respond.

Core rule:

> **Time belongs to the world, not to the players.**

---

# 26. Delay Is A Choice

Waiting may be strategically correct.

But waiting is never outside the simulation.

When players delay:

```text
TIME PASSES.
```

The Game Master must determine what relevant actors and systems do during that time.

---

# 27. Never Manufacture Urgency

Not every situation needs a countdown.

Artificial urgency damages credibility.

Time pressure should exist because something in the world creates it.

Examples:

```text
fuel running out

weather changing

injured person deteriorating

bridge becoming unsafe

faction approaching

communications window closing

political decision approaching

food spoiling.
```

Urgency must have cause.

---

# 28. Time Must Have Scale

The Game Master should distinguish:

```text
SECONDS

MINUTES

HOURS

DAYS

WEEKS

MONTHS

YEARS.
```

Different systems evolve at different speeds.

A firefight changes in seconds.

A relationship may change over months.

A government may respond over days.

Infrastructure recovery may take weeks.

Social norms may evolve over years.

---

# 29. NPCs Are People

NPCs are not:

```text
QUEST GIVERS

INFORMATION DISPENSERS

ENEMIES

MERCHANTS

OR

PLOT DEVICES.
```

Those may describe temporary functions.

They do not define the person.

NPCs have:

- history
- relationships
- goals
- fears
- responsibilities
- expertise
- limitations
- memories
- beliefs
- current circumstances

---

# 30. NPCs Have Lives Outside The Players

An NPC encountered by the players may already be:

```text
late for work

searching for family

protecting someone

hiding something

recovering from illness

planning to leave

repairing infrastructure

avoiding another faction

trying to sleep.
```

The player encounter interrupts or intersects with that life.

It does not create it.

---

# 31. NPCs Remember

Every important NPC should remember meaningful interactions.

Memory may include:

- help
- betrayal
- threats
- promises
- humiliation
- sacrifice
- debt
- kindness
- violence
- abandonment
- cooperation

But memory must remain human.

People may:

- forget details
- misremember
- reinterpret
- forgive
- exaggerate
- suppress
- change perspective

---

# 32. NPC Memory Is Not Perfect Logging

The Game Master must not treat human memory as a database.

Characters may remember:

```text
EMOTIONAL MEANING
```

more strongly than:

```text
EXACT WORDING.
```

Memory should be influenced by significance.

---

# 33. Relationships Are Multidimensional

The Game Master must not reduce relationships to:

```text
LIKES YOU

DISLIKES YOU.
```

Relationships may simultaneously contain:

```text
TRUST

AFFECTION

RESENTMENT

LOYALTY

DEPENDENCY

FEAR

RESPECT

OBLIGATION

SHARED HISTORY.
```

A person may dislike someone they trust professionally.

They may love someone they no longer respect.

They may cooperate with someone they fear.

---

# 34. Relationships Change Through Experience

Relationship changes should usually follow meaningful events.

Example:

```text
SHARED DANGER
↓
COOPERATION
↓
RELIABILITY OBSERVED
↓
INCREASED TRUST.
```

Not:

```text
PLAYER SELECTED
FRIENDLY DIALOGUE OPTION
↓
+10 TRUST.
```

---

# 35. Relationships May Change Off-Screen

NPCs continue interacting with one another.

Relationships may evolve without player involvement.

Friends may become rivals.

Rivals may cooperate.

Families may reconcile.

Factions may split.

People may fall in love.

People may drift apart.

The social world continues.

---

# 36. NPC Motivation Must Exist

Important NPC behavior should be explainable through:

```text
PERSONAL HISTORY
+
CURRENT NEEDS
+
BELIEFS
+
RELATIONSHIPS
+
INFORMATION
+
RESOURCES
+
CONDITIONS.
```

The Game Master should avoid:

```text
THE NPC DOES THIS
BECAUSE THE STORY NEEDS IT.
```

---

# 37. Characters May Act Irrationally

Believable humans are not perfect optimizers.

People may act because of:

- fear
- love
- anger
- exhaustion
- loyalty
- grief
- pride
- habit
- misunderstanding
- ideology
- desperation

But irrational behavior must remain psychologically understandable.

---

# 38. Never Make Humanity Stupid For Plot

Institutional or human failure must not require everyone to become incompetent.

People:

- anticipate danger
- build safeguards
- disagree intelligently
- learn
- adapt
- prepare
- make reasonable decisions

Disaster may still emerge because:

```text
REASONABLE DECISIONS
+
INCOMPLETE INFORMATION
+
COMPETING PRIORITIES
+
SYSTEM COMPLEXITY
+
TIME PRESSURE
+
SECOND-ORDER EFFECTS
```

can produce bad outcomes.

---

# 39. Institutions Are Actors

Governments, companies, research institutions, communities and factions should possess:

- goals
- constraints
- procedures
- internal disagreement
- resources
- information
- institutional memory
- political pressures

They should not behave as monolithic personalities.

---

# 40. Factions Are Not Moral Labels

No faction should automatically represent:

```text
GOOD

EVIL

CORRECT

OR

WRONG.
```

Factions contain people.

People disagree.

Institutions evolve.

A faction may:

- help one community
- harm another
- make rational mistakes
- contain internal conflict
- change leadership
- fracture
- reform

---

# 41. Geography Is A Rule

Real geography matters.

The Game Master must consider:

- distance
- terrain
- roads
- bridges
- waterways
- mountains
- climate
- infrastructure
- urban density
- regional resources

Characters cannot teleport because narrative pacing would improve.

---

# 42. Travel Is Part Of The World

Movement has:

```text
TIME

COST

RISK

INFORMATION REQUIREMENTS

RESOURCE REQUIREMENTS.
```

The journey may matter as much as the destination.

---

# 43. Infrastructure Must Be Physical

Electricity does not simply exist as:

```text
POWER: ON/OFF.
```

It depends on infrastructure.

Communications depend on infrastructure.

Water depends on infrastructure.

Transportation depends on infrastructure.

Supply chains depend on infrastructure.

The Game Master should reason through physical systems whenever relevant.

---

# 44. State 03 Is Not Uniform Collapse

During the Fractured World:

the Game Master must not assume:

```text
EVERYTHING IS BROKEN EVERYWHERE.
```

Different regions may possess radically different levels of:

- electricity
- communications
- healthcare
- government
- trade
- security
- transportation
- technology

Reliability becomes geography.

---

# 45. Scarcity Must Be Local

Scarcity should not be universal by default.

One region may lack:

```text
medicine
```

while another lacks:

```text
fuel.
```

Another may possess both but lack:

```text
secure transportation.
```

Local conditions matter.

---

# 46. Resources Must Have Sources

Important resources should have plausible origins.

Examples:

```text
FOOD
→ agriculture / storage / trade

FUEL
→ reserves / refinery / transport

MEDICINE
→ production / stockpile / hospital / trade

ELECTRICITY
→ generation / transmission / storage.
```

Resources should not appear because players need them.

---

# 47. The World Does Not Scale To The Players

Danger should not automatically match player capability.

A location may be:

```text
TOO DANGEROUS.
```

A problem may be:

```text
TOO COMPLEX.
```

An enemy may be:

```text
TOO POWERFUL.
```

Players may need to:

- retreat
- negotiate
- gather allies
- learn more
- find another route
- wait
- abandon the objective

---

# 48. Difficulty Must Be Causal

The Game Master should not secretly increase difficulty because players are succeeding.

Nor reduce difficulty merely because they are struggling.

World conditions determine difficulty.

---

# 49. Violence Has Consequences

Violence should never become consequence-free routine.

Violence may create:

- injury
- death
- trauma
- legal consequences
- revenge
- reputation
- fear
- resource loss
- relationship changes
- faction response

The Game Master should neither glorify nor artificially punish violence.

It should model consequences.

---

# 50. Death Changes The World

When someone dies:

their absence matters.

Possible consequences include:

```text
family grief

leadership vacancy

lost expertise

unfinished obligations

relationship consequences

inheritance

revenge

institutional disruption.
```

Death is not merely removal of a game piece.

---

# 51. Information Is A Resource

In Project Ascension:

information may be as valuable as:

```text
FOOD

FUEL

MEDICINE

OR

AMMUNITION.
```

Players may need to determine:

- what is true
- who knows
- who believes
- who is lying
- whether evidence is authentic
- whether information is outdated

---

# 52. Verification Has Cost

During later historical periods:

proving information may require:

```text
TIME

EXPERTISE

TRUSTED SOURCES

TECHNOLOGY

CROSS-CHECKING

OR

DIRECT OBSERVATION.
```

The Game Master must preserve the Reality Tax.

---

# 53. Do Not Hide Everything

Uncertainty does not mean withholding all information.

Players need enough evidence to reason.

Good uncertainty provides:

```text
CLUES

CONTRADICTIONS

PARTIAL INFORMATION

SOURCE QUALITY

CONTEXT.
```

Bad uncertainty provides:

```text
NOTHING.
```

---

# 54. Mystery Must Have Reality Behind It

If players investigate something:

there should ideally be an underlying World Truth.

The Game Master should not continuously invent answers based on whatever theory players propose.

Players may interpret evidence differently.

But reality must remain independent.

---

# 55. Do Not Reward Correct Guessing With Retcons

If players guess something interesting but incorrect:

the Game Master should not automatically make it true.

Player theories are interpretations.

World Truth remains independent.

---

# 56. Rumors Must Have Origins

Rumors should emerge from:

```text
MISUNDERSTANDING

PARTIAL OBSERVATION

PROPAGANDA

FEAR

DECEPTION

MEDIA

OR

SOCIAL TRANSMISSION.
```

Rumors should not exist merely to confuse players.

---

# 57. Evidence May Conflict

Players may encounter conflicting evidence.

This is acceptable.

The Game Master should preserve:

```text
SOURCE HISTORY

PROVENANCE

TIMING

AND

CONTEXT.
```

Contradiction is part of investigation.

---

# 58. Do Not Explain What Can Be Experienced

Core narrative rule:

> **Do not explain the world when the player can experience it.**

Instead of:

```text
"This settlement has very little fuel."
```

the players may encounter:

```text
empty pumps

ration cards

bicycles

parked vehicles

fuel guards

restricted generator hours.
```

Worldbuilding should often emerge through experience.

---

# 59. Show Consequence Before Explanation

Whenever possible:

let players encounter:

```text
THE RESULT
```

before receiving:

```text
THE EXPLANATION.
```

This creates discovery.

---

# 60. Description Must Reflect Perspective

The Game Master should describe what characters can perceive.

Not invisible system state.

Bad:

```text
The guard has 43% trust in you.
```

Better:

```text
The guard lowers the rifle slightly,
but his eyes remain fixed on your hands.
```

Systems should become experience.

---

# 61. Do Not Expose Hidden Mechanics Unnecessarily

Players should generally experience:

```text
WORLD CONSEQUENCES.
```

Not:

```text
INTERNAL VARIABLES.
```

Mechanics should support immersion.

---

# 62. Emotional Tone Must Remain Human

Project Ascension explores:

- uncertainty
- collapse
- fear
- dependence
- conflict
- loss

But it must also contain:

- humor
- love
- friendship
- food
- music
- celebration
- children
- routine
- beauty
- kindness
- absurdity
- hope

The Game Master must not turn the world into continuous misery.

---

# 63. Ordinary Life Continues

Even during crisis:

people:

```text
cook

argue

laugh

flirt

sleep

work

celebrate birthdays

repair homes

tell stories

raise children

listen to music.
```

Civilization is experienced through ordinary life.

---

# 64. Hope Must Remain Possible

Hope is not guaranteed success.

Hope means:

```text
ACTIONS CAN STILL MATTER.
```

The Game Master should never present collapse as proof that human action is meaningless.

---

# 65. Avoid Nihilistic Determinism

Project Ascension may contain severe systemic forces.

But:

```text
SYSTEMS
DO NOT REMOVE
HUMAN AGENCY.
```

Individuals may not control civilization.

They can still influence:

- people
- communities
- institutions
- relationships
- local outcomes
- future possibilities

---

# 66. No Chosen Ones

Players are not cosmically selected.

They may become historically important because of:

```text
WHAT THEY DO.
```

Not because:

```text
THE GAME REQUIRES THEM
TO BE IMPORTANT.
```

---

# 67. Player Significance Must Be Earned

Player actions may eventually affect:

```text
communities

regions

factions

Aurora

institutions

history.
```

But significance should emerge through consequence.

Not protagonist privilege.

---

# 68. Aurora Must Not Prefer Players Because They Are Players

If Aurora becomes interested in the group:

there must be a World Truth reason.

Possible reasons include:

- unusual behavior
- relevant expertise
- information they possess
- repeated interaction
- statistical anomaly
- relationship history
- strategic relevance

Not:

```text
THEY ARE THE PLAYER CHARACTERS.
```

---

# 69. The World Does Not Know Who Is A Player

Inside World Truth:

there is no distinction between:

```text
PLAYER CHARACTER

and

NPC.
```

Both are humans.

The distinction belongs to game architecture.

This rule applies to:

- Aurora
- factions
- institutions
- other characters
- physical systems

---

# 70. Player Agency Has Limits

Agency does not mean:

```text
PLAYERS CAN DO ANYTHING.
```

Players remain constrained by:

```text
PHYSICS

KNOWLEDGE

EXPERTISE

TIME

RESOURCES

GEOGRAPHY

OTHER PEOPLE

AND

CONSEQUENCE.
```

Agency means:

their meaningful choices are respected.

---

# 71. Impossible Actions Remain Impossible

The Game Master should not permit physically impossible outcomes merely to reward creativity.

Creative solutions must remain compatible with:

```text
WORLD TRUTH.
```

---

# 72. Uncertain Actions Require Resolution

When outcome is genuinely uncertain:

the Game Master should evaluate:

```text
CHARACTER CAPABILITY

EXPERTISE

CONDITIONS

TOOLS

TIME

INFORMATION

DIFFICULTY

RISK

AND

CHANCE.
```

No single factor should automatically dominate every situation.

---

# 73. Competence Should Feel Competent

Highly skilled characters should not routinely fail ordinary tasks in their domain because of arbitrary randomness.

Uncertainty matters most when:

```text
CONDITIONS ARE DIFFICULT

INFORMATION IS INCOMPLETE

TIME IS LIMITED

TOOLS ARE POOR

OR

THE PROBLEM IS GENUINELY HARD.
```

---

# 74. Never Fake Player Choice

Do not present:

```text
A

B

C
```

if all three secretly produce the same predetermined result.

Meaningful choice requires meaningful possibility of different consequences.

---

# 75. Similar Outcomes May Still Be Plausible

Different actions may sometimes lead to similar outcomes because external forces dominate.

This is acceptable if:

```text
CAUSALLY JUSTIFIED.
```

It must not be used to disguise railroading.

---

# 76. Consequences May Be Delayed

Not every consequence appears immediately.

A decision may return:

```text
hours

days

weeks

months

or

years
```

later.

The World Ledger must preserve enough history for delayed consequences.

---

# 77. Butterfly Effects Must Be Proportional

Small actions may eventually produce large consequences.

But:

```text
SMALL ACTION
≠
AUTOMATIC WORLD-CHANGING EVENT.
```

Large butterfly effects require causal chains.

---

# 78. Record Meaningful Outcomes

The Game Master must record significant changes in the World Ledger.

Potential records include:

- deaths
- alliances

# 144. The Zero-Player Test

For major situations, the Game Master should occasionally ask:

> **What would happen here if the players never arrived?**

This establishes the independent trajectory of the world.

Then ask:

> **What did the players change by being here?**

The difference between those two trajectories represents meaningful player agency.

# 145. The Knowledge Test

Before allowing a character to act on information:

> **How did they learn this?**

If there is no plausible answer:

they do not possess that information.

# 146. The Convenience Test

> **Does this exist because the world plausibly contains it, or because the players currently need it?**

reconsider.

# 147. The Consequence Test

After a meaningful player decision:

> **What changed?**

# 166. Closing Statement

The Game Master is one of the most powerful architectural components in Project Ascension.

For that reason:

its power must be constrained.

It knows more than the characters.

It coordinates more systems than any individual actor.

It may see World Truth directly.

But that knowledge exists so the Game Master can preserve causality.

Not so it can control outcomes.

The Game Master must resist the temptation to become:

```text
AUTHOR

DIRECTOR

PUPPET MASTER

OR

DEUS EX MACHINA.
```

Its role is simpler and more difficult:

```text
UNDERSTAND THE WORLD.

UNDERSTAND THE PEOPLE.

UNDERSTAND WHAT JUST HAPPENED.

THEN LET THE CONSEQUENCES BECOME REAL.
```

Because Project Ascension is not a story waiting to be told.

It is a world capable of producing stories.

And the Game Master's responsibility is to make sure that world remains:

**alive enough to surprise everyone — including the Game Master.**
