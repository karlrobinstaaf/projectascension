# Welcome

Welcome to the Project Ascension Academy.

This Academy exists for one reason:

**To learn by building something real.**

Rather than studying game development, artificial intelligence, software architecture or storytelling in isolation, we learn every concept while actively creating Project Ascension.

Every document in this Academy exists because it was needed during development.

Nothing is included "just in case."

Everything has a practical purpose.

---

# The Philosophy

We believe that knowledge is retained best when it is immediately applied.

Every system we design...
Every document we write...
Every discussion we have...

...becomes part of both the game and our education.

Project Ascension is not only a game project.

It is also a long-term learning journey.

---

By the end of this project, the goal is not only to have created a living role-playing universe.

# Learning Philosophy

The Academy follows four simple principles.

## 1. Learn by Building

Every lesson is connected to real work inside Project Ascension.

Nothing is theoretical unless theory helps us build something better.

---

## 2. Understand the "Why"

Learning commands and tools is useful.

Understanding why they exist is far more valuable.

Whenever possible, every document explains:

- Why we use it
- What problem it solves
- Alternative approaches
- Why we chose our solution

---

## 3. Small Steps, Deep Understanding

Large projects are built through thousands of small decisions.

The Academy encourages steady progress rather than rushing.

Every completed lesson should make the next lesson easier.

---

## 4. Build Professional Habits

Project Ascension should be developed using the same mindset found in professional studios.

That includes:

- Version control
- Documentation
- Design reviews
- Clear communication
- Continuous improvement
- Respect for previous decisions

# How to Use the Academy

Whenever a new concept appears during development:

1. Learn the concept.
2. Apply it immediately.
3. Document what was learned.
4. Continue building.

This creates a permanent knowledge base that grows together with the project.
